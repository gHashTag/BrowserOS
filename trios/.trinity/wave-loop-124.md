## Валидация структурного лекарства (в ТЕМП-каталоге, рабочий
артефакт не тронут)

Вызов эмитa build.sh:607 + `-enable-library-evolution
-emit-module-interface-path`:
- emit EXIT=0, 0 ошибок — флаг совместим с API всех 15 файлов;
- эмитятся ОБА interface-файла (QueenCore.swiftinterface и
  .private.swiftinterface) — при голом -enable-library-evolution без
  -emit-module-interface-path они НЕ появляются (проверено первым
  прогоном);
- consumer-typecheck против эмитнутого модуля — зелёный.
По module stability (Swift.org): новый компилятор импортирует
interface, собранный старым — ровно падающее направление. Кросс-версия
не проверена живьём (старого тулчейна нет) — помечено честно.

## Обзор (takeaway)

Бинарный .swiftmodule жёстко залочен под версию компилятора (даже
патч-версия ломает импорт); прочная раздача/prebuilt —
library evolution + .swiftinterface, и собирать старейшим нужным
тулчейном (forward-only). Для trios флаг закрывает направление
«артефакт старее сюит» без соглашения о тулчейнах.
Sources: [Swift.org library evolution](https://swift.org/blog/library-evolution/),
[классическая ошибка RxSwift](https://stackoverflow.com/questions/58654714/module-compiled-with-swift-5-1-cannot-be-imported-by-the-swift-5-1-2-compiler),
[ограничение forward-only](https://blog.eidinger.info/why-your-xcode-version-still-matters-with-module-stability).
