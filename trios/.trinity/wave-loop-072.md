## Competitor research

- [SO: flock with timeout can't kill parent](https://stackoverflow.com/questions/2896633/why-doesn-t-bash-s-flock-with-timeout-exit-if-it-fails-to-acquire-the-lock):
  классика «первая строка рецепта висит в CI» — таймаут внутри не может
  убить родителя. Takeaway: таймаут обязан жить СНАРУЖИ зависающей фазы.
- [flock(2)](https://man7.org/linux/man-pages/man2/flock.2.html) +
  [flock несправедлив](https://code.jjb.cc/linux-flock-does-not-provide-fair-locking):
  очередь без FIFO может голодать вечно. Takeaway: ожидание лока без
  своего бюджета — всегда потенциальное навсегда.
- [stress-make](https://github.com/lanl/stress-make): гонки Makefile
  воспроизводятся нагрузкой. Takeaway на будущее: наш поллинг-монитор —
  дешёвый cousin stress-make для одной цели.

## Plan

1. W1 → собственный watchdog в lock-строке: старт при входе в фазу, тот же
   бюджет, гашение при нормальном завершении строки.
2. Погасить свой висший прогон поколенческим циклом (паттерн волны 070).

## Report

- **W1 сделан и доказан.** Lock-watchdog вставлен в начало lock-фазы
  (Makefile:~1793-1803): `( sleep $(CASSETTE_TOTAL_BUDGET) && kill -TERM $$$$ )
  & lwpid=$$!` + раздельные trap-ы, гашение в конце строки. Изолированный
  тест: kill-путь exit 124 на 3-й секунде, clean-путь exit 0. `make -n`
  несёт 4 вхождения lwpid, `make make-dollars` [OK].
- **Прогон 40723 погашен** поколенческим циклом: ждуны 0, мои make 0,
  лок снят. Дерево чисто для следующей волны.
- **W2 записан** (эхо stdout) — пере-интерпретация ночных логов: часть
  «моих» красных строк были чужими уровнями. Отмечено в отчёте для
  честности истории.
- Guard всё ещё без боевого выстрела (W3 открыт): цепь умерла на 3-м
  уровне по чужой причине (check-selftest).
