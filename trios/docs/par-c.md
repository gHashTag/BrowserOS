# File Boundaries

1. Each layer of the Trios architecture (Core, Infrastructure, Application, Presentation) owns a distinct set of Swift files. Core types like `ChatMessage`, `ChatRole`, and `SSEEvent` live in `ChatMessage.swift` and `ChatEvents.swift`, defining plain data models and enums with no framework dependencies. This separation keeps the innermost ring free from side effects and allows downstream layers to import only the contracts they need.

2. The Infrastructure layer wraps transport and persistence concerns in dedicated files: `SSETransport.swift` handles URLSession streaming, `HealthCheckTransport.swift` performs GET `/health` pings, and `ConversationPersister.swift` writes to `UserDefaults`. Each file maps one-to-one to a protocol declared in Core, so swapping an implementation means adding a file, not editing existing ones. The parser bridge `UIMessageStreamParser.swift` converts raw `SSEEvent` values into `ParserAction` items consumed by the Application layer.

3. The Application and Presentation layers complete the onion. `ChatViewModel.swift` coordinates message state, streaming, and throttling through `ConversationStateMachine.swift` (an actor) and `EventThrottler.swift`. Presentation files — `ChatPanelView.swift`, `MessageBubbleView.swift`, `ToolCallCardView.swift`, and `GlassmorphismBackground.swift` — render what the view model exposes. A file never reaches across two layers; when logic from an outer ring is needed it is pulled inward through a protocol, preserving the directional dependency rule of the ring.
